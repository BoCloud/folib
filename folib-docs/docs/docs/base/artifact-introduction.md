# 什么是制品？

## 概述

**制品**（Artifact）是指由源代码经过编译、打包生成的二进制文件。不同编程语言对应不同格式的二进制文件，这些文件通常用于服务器运行或作为编译依赖。制品管理是配置管理的重要组成部分，贯穿软件构建、分发、部署的全生命周期。

---

## 制品的基本概念

制品包含以下特征：
- **内容类型**：类文件（如Java字节码）、C对象文件、文本文件、二进制文件等。
- **存储格式**：支持多种语言和场景的标准化格式（如JAR、Docker镜像等）。
- **核心作用**：确保构建一致性、依赖安全性，提升软件交付效率。

---

## 常见的制品格式

制品按用途可分为两大类：
### 1. 依赖维度

用于管理代码编译或运行时所需的依赖包，常见格式包括：
- **Java**: JAR、WAR、EAR
- **JavaScript**: NPM包
- **.NET**: NuGet包
- **Ruby**: Gems包
- **PHP**: Composer依赖
- **Go**: Go Modules
- **Python**: Wheel、Egg、Conda包
- **其他语言**:Rust: Crate包，Perl: CPAN模块，R: CRAN包 ，Swift: SPM包，Dart: Pub包，Haskell: Cabal包，鸿蒙Ohpm: HAR包

### 2. 成品软件包维度
用于部署或分发的最终软件包，常见格式包括：
- **通用包**: ZIP、tar.gz
- **可执行文件**: .exe、.sh、Android APK
- **容器化制品**: Docker镜像、Helm包
- **系统包**: RPM包
- **AI模型文件**
- 预训练模型文件（如TensorFlow SavedModel、PyTorch .pt、ONNX格式）
- 推理引擎文件（如TensorRT引擎、Core ML模型）
- **OTA更新包**
   - 全量发布包（完整系统/应用镜像，如Android OTA zip）
   - 差量更新包（仅包含版本差异的增量包，如BSDiff格式）

---

## 制品的分类场景

### 按供给场景分类
| 类型     | 描述                                                                 |
|----------|--------------------------------------------------------------------|
| **一方包** | 同系统内各模块的依赖包（如微服务间的内部SDK）                          |
| **二方包** | 公司内部跨团队/跨项目的依赖包（如其他部门提供的公共组件）                |
| **三方包** | 外部开源或第三方提供的依赖包（如Apache、Google等开源库）               |



## 总结
制品是软件交付流程中的核心载体，通过制品库实现全生命周期的管理，能够显著提升构建一致性、保障依赖安全，并加速交付效率。无论是开发阶段的依赖包，还是最终部署的软件包，统一管理制品是现代化 DevOps 实践的重要基石。
